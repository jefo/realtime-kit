# Терминалы ломаются не на графиках

Черновик статьи для Habr / LinkedIn. Ссылки подставить после публикации
репозитория.

---

Все думают, что торговый терминал — это график. График — самое простое.
Библиотека свечей есть у всех, а если нет — берётся `lightweight-charts` и
рисуется за вечер.

Ломается всё вокруг: поток.

Один виджет хочет стакан, второй — сделки, третий — funding, четвёртый —
свечи. Каждый открывает свой WebSocket или EventSource. Каждый переподключается
сам. Каждый тянет данные, даже когда вкладка свёрнута. Через месяц в проде
десятки соединений, дубли подписок, утечки памяти и «UI подтормаживает, когда
много символов».

Я собрал четыре пакета, которые закрывают эту часть. Они не про графики. Они
про то, что между биржей и интерфейсом.

## 1. `@rtkit/market-ingest` — один формат вместо схем каждой биржи

Binance присылает `bookTicker`, `kline`, `markPriceUpdate` и `forceOrder`.
У Bybit другие поля, у OKX третьи. Если фронтенд знает про эти различия, он
никогда не перестанет меняться.

Пакет нормализует всё в четыре события:

```ts
type MarketEvent =
  | { type: "quote"; bid; ask; bidSize?; askSize?; ... }
  | { type: "kline"; interval; ohlcv; closed; ... }
  | { type: "funding"; fundingRate; markPrice?; ... }
  | { type: "liquidation"; side; price; quantity; usd; ... }
```

Внутри — `MarketHub`: считает ссылки на подписки, запускает поток биржи на
первом подписчике и останавливает на последнем, хранит последнее событие в
кэше. Два виджета на один символ — одна подписка на бирже.

## 2. `@rtkit/subscriptions` — один EventSource на сессию

Классическая ошибка — по одному стриму на виджет. Браузер упирается в лимит
соединений, сервер — в количество подписок.

Здесь клиент присылает набор подписок один раз, получает `sessionId` и слушает
один поток. Внутри:

- детерминированный ключ подписки (`ticker:{"symbol":"BTC"}`), не зависящий от
  порядка полей;
- очередь на сессию с явной политикой переполнения: выкинуть старое или
  разорвать соединение;
- lifecycle-хуки: первый подписчик включает апстрим, последний выключает;
- heartbeat, чтобы прокси не убил тихое соединение.

Медленный клиент больше не растёт в памяти — он теряет старые события
предсказуемо.

## 3. `@rtkit/udf-datafeed` — свои данные в график

TradingView-совместимый график умеет работать с UDF: `config`, `symbols`,
`history`, `time`, `search`. Каждый, кто подключает свои данные, пишет эти
шесть endpoint-ов заново и наступает на одни и те же грабли: миллисекунды
вместо секунд, дубли баров, `no_data` вместо `error`, таймауты.

Пакет даёт сервер и один интерфейс `DataProvider`. Дальше — либо
`MemoryProvider` для демо, либо `BinanceProvider` для реальных данных. График
не знает, откуда пришли свечи.

## 4. `@rtkit/terminal-kit` — UI без CSS-фреймворка

Последний слой — интерфейс. Плотная таблица с сортировкой, стакан с depth-барами,
спарклайн, метрики и статус соединения. Svelte 5, тёмная и светлая темы, две
плотности, никаких зависимостей.

Это не «компоненты на всё». Это ровно те экраны, которые в терминале дорого
доводить: таблица, которая не разваливается от тысячи строк, стакан с
агрегацией по тику и график без библиотеки. Всё остальное — на ваш вкус.

## Что я сознательно не стал делать

- **Не тащить TradingView Charting Library.** Она проприетарная. UDF — открытый
  протокол, библиотека не нужна.
- **Не делать клон Coinglass.** Рынок занят, данные дорогие, а продукт без
  биллинга и дистрибуции остаётся демо.
- **Не завязываться на Redis.** Кэш — интерфейс; память по умолчанию, Redis
  опционально.

## Что внутри

- 137 тестов на границы протоколов: ключи, backpressure, реконнект, форматы
  ответов, сортировка и математика стакана.
- Четыре независимых пакета, MIT, без вендорских зависимостей.
- Живой пример: Binance WS → нормализация → SSE → браузер.
- Демо-график на своих данных, без TradingView-библиотеки.
- Svelte-терминал: таблица, стакан, спарклайн, метрики, две темы.

Репозиторий: `https://github.com/jefo/realtime-kit`

Если вы строите терминал, аналитику или проп-панель и упираетесь в поток —
напишите. Обычно это 2–4 недели на интеграцию, а не полгода.

## Короткая версия для LinkedIn

Терминалы ломаются не на графиках, а на потоке.

Собрал четыре пакета, которые закрывают скучную часть:
— SSE-шлюз: один поток на сессию, подписки, backpressure;
— UDF-сервер: свои данные в TradingView-совместимый график;
— ingest: quote/kline/funding/liquidation в одном формате;
— UI: таблица, стакан, спарклайн и темы на Svelte 5.

137 тестов, живое демо Binance WS → SSE, MIT. Ссылка в комментарии.
